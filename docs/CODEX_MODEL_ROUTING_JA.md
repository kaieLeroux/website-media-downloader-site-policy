## 実装した原則

目的は、最も大きいモデルを常用することではありません。まず必要な
正確さを満たし、その同じ合格条件を満たせる範囲でモデルと推論量を
下げます。文章が自然であることだけを合格とはせず、ビルド、テスト、
差分レビューなどの観測可能な結果で判定します。

このリポジトリでは、親タスクを `gpt-5.6-sol` の Medium にしています。
これは曖昧な依頼を受け取り、作業を分解し、最後の統合判断をするための
安全側の既定値です。実作業は次のように振り分けます。

| 担当 | モデル | 推論量 | 主な用途 |
| --- | --- | --- | --- |
| 親 | GPT-5.6 Sol | Medium | 要件整理、計画、統合、最終判断 |
| `implementer` | GPT-5.6 Terra | Medium | 範囲が明確な通常実装 |
| `explorer` | GPT-5.6 Terra | Low | 読み取り中心のコード調査 |
| `/review` | GPT-5.6 Terra | Medium | 通常の差分レビュー |
| `reviewer` | GPT-5.6 Terra | High | 複数ファイルにまたがるロジックレビュー |
| `deep_reviewer` | GPT-5.6 Sol | High | 権限、認証、セキュリティ、公開処理、設計変更 |
| `tester` | GPT-5.6 Luna | Low | 決められたテストの実行と結果採取 |
| `mechanical_worker` | GPT-5.6 Luna | Low | 定型変換、分類、反復処理 |

テスト失敗の解析は、テスト実行そのものとは別です。Luna は失敗内容を
採取して親へ返し、原因究明や修正は Terra 以上へ渡します。これにより、
単純なコマンド実行だけで大きな推論枠を消費しません。

## コードレビューを独立させた仕組み

`.codex/config.toml` の `review_model` に `gpt-5.6-terra` を指定しました。
そのため、通常の `/review` は親の Sol と別のモデルで動きます。

ただし、現在の `review_model` 設定はレビュー専用の推論量まで動的に
変える仕組みではありません。そこで、通常レビューは Terra Medium、
複雑なレビューは `reviewer` の Terra High、重大なレビューだけ
`deep_reviewer` の Sol High、という三段階にしました。Max や Ultra は
既定にせず、High で実際に不足が確認された難問に限ります。

## コンテキストを膨らませない仕組み

Sol、Terra、Luna はいずれも 1.05M トークンのコンテキストと 128K
トークンの最大出力を持ちます。しかし、上限内なら何を詰め込んでも
精度が一定、という保証ではありません。このリポジトリでは次を守ります。

- まず `git diff`、入口となる関数、関連ファイルだけを読む。
- `src/libraries/` の圧縮済み第三者コードは、関係する場合だけ読む。
- サブエージェントには担当範囲と完了条件だけを渡し、生の大量出力では
  なく、ファイル位置つきの要約を返させる。
- 単純な一ファイル修正ではサブエージェントを作らない。
- 同じ大きな文脈を複数のエージェントに重複して読ませない。
- 27.2万入力トークンを超える API 呼び出しは長文料金になるため、巨大な
  入力を一回にまとめず、独立した責務ごとに切り分ける。

## 費用の目安

OpenAI API の標準料金は、100万トークンあたり次の通りです。ChatGPT の
クレジット消費は API のドル料金と同一ではないため、ここでは相対的な
判断材料として使います。

| モデル | 入力 | キャッシュ入力 | 出力 |
| --- | ---: | ---: | ---: |
| GPT-5.6 Sol | $4.00 | $0.40 | $20.00 |
| GPT-5.6 Terra | $2.00 | $0.20 | $12.00 |
| GPT-5.6 Luna | $0.20 | $0.02 | $1.20 |

つまり、Luna は Sol に対して入力単価が 20 分の1、出力単価が約 17 分の1
です。定型テストや機械的処理を Luna へ分ける効果が大きく、判断の難しい
親タスクだけ Sol に残す方が、全体を Luna に落として失敗を増やすより
合理的です。

## 各製品で自動化できる範囲

| 製品 | このリポジトリから設定できること | 製品画面で必要なこと |
| --- | --- | --- |
| Codex Local／CLI／IDE／デスクトップ | 信頼済みリポジトリでは `.codex/config.toml`、`AGENTS.md`、専用エージェント、スキルが読み込まれる | 別の全リポジトリにも適用する場合だけ、下記の一回インストールを行う |
| Codex Cloud | `AGENTS.md` とリポジトリ内の作業規則を共有できる | Cloud チャットの既定モデルは現在変更できないため、必要なら新しいチャットで選ぶ |
| ChatGPT Work | Work でリポジトリを扱う際の指示やスキルを共有できる | 作成欄の下にあるモデル／推論量選択で、その親タスクの設定を選ぶ |
| 通常の ChatGPT Chat | この Git リポジトリの設定だけで全チャットの親モデルを強制変更することはできない | モデル選択で Sol Medium を安全側の既定にし、明確な軽作業だけ Terra／Luna 相当へ下げる |

ChatGPT Work や通常 Chat では、テキストのカスタム指示だけで実行中の親
モデルを自動交換することはできません。モデル選択は作成欄のモデル選択
UIが管理します。Ultra は、独立して並列化できる大きな仕事に限ります。

## スキル化と「学習」の扱い

この設定だけで、個人専用の教師あり学習や強化学習を GPT-5.6 に直接
かけることはできません。また、会話で数回訂正しただけでモデル本体が
恒久的に再学習されるわけでもありません。

その代わり、今回の成功手順を `.agents/skills/model-routing/` にスキルと
して保存し、設定検査と導入テストを追加しました。今後、同じ失敗が再現
した場合は、会話の記憶だけに頼らず、再現条件、正しい経路、合格判定を
スキルまたは `AGENTS.md` に反映します。これは内容を人間が監査でき、
Git の履歴で戻せるため、現時点で利用できる最も安全な継続改善です。

## Codex Local 全体へ一回で適用する

リポジトリのルートで次を実行します。

```bash
python3 scripts/install_codex_user_policy.py --apply
```

このスクリプトは既存設定をバックアップしてから、モデル既定値、レビュー
モデル、専用エージェント、モデル振り分けスキル、全体用の短い指示を
`CODEX_HOME`（未設定なら `~/.codex`）へ入れます。既存の他の設定や指示は
残します。Python 3.11 以上が必要です。

適用前に対象だけ確認したい場合は、`--apply` を付けずに実行します。
適用後は新しい Codex セッションを開始し、`/status` と `/model` で現在値を
確認してください。

## 品質保証について

どのモデル、推論量、スキルも「常に誤りがない」ことまでは理論的にも
保証できません。今回保証できるのは、仕事の種類に応じて費用を抑える
選定経路、重大作業の自動格上げ、そしてビルド・テスト・レビューを通ら
なければ完了にしない仕組みです。これは、保証不能な完全無欠を宣言する
代わりに、失敗を検出して止められる現実的な品質保証です。
